# Deploy on Render

This repository includes a Render Blueprint in `render.yaml`. It creates a Docker-based web service and configures `/readyz` as its health check. The API requires MySQL; Render does not provide a managed MySQL database in this Blueprint, so create or use an externally hosted MySQL 8 database and provide its connection settings to the service.

## Create the service

1. Push this repository to a Git provider supported by Render.
2. In the Render Dashboard, choose **New > Blueprint**, connect the repository, and apply the Blueprint. If the app files are in a subdirectory, set the Blueprint root directory to that directory.
3. During setup, enter the external MySQL host, database name, username, and password when prompted for `DB_HOST`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD`. Set `DB_PORT` if the database does not use `3306`.
4. If the database provider requires a CA certificate for TLS, make it available to the service and set `DB_SSL_CA` to its filesystem path. The app uses TLS when this variable is set.
5. Wait for the first deploy to become healthy, then open the service's `onrender.com` URL.

`ADMIN_TOKEN` and `USER_TOKEN_SECRET` are generated by the Blueprint. Keep both private. To rotate them, set new values in the Render service's Environment page and redeploy. Do not commit database credentials or secret values to the repository.

## Startup and schema

The Docker image runs `python init_db.py` before starting Gunicorn. This creates missing tables and applies the metric event enum update for existing databases. The MySQL account must be allowed to create and alter tables. Schema initialization is safe to repeat; it does not delete existing data.

The service listens on Render's injected `PORT`. Render checks `GET /readyz`, which returns success only when the database is reachable. `GET /healthz` is a process liveness check, and `GET /metrics` exposes Prometheus metrics.

## Verify the deployment

```sh
curl -i https://<your-service>.onrender.com/healthz
curl -i https://<your-service>.onrender.com/readyz
curl -i https://<your-service>.onrender.com/metrics
```

Expected results are HTTP 200 for all three endpoints when the database is configured and reachable. `/metrics` returns Prometheus text including confirmed, cancelled, declined, and available-seat metrics.

Free Render web services may spin down after inactivity and take time to respond to the first request after waking. Choose a paid instance if you need continuously warm service availability. The external MySQL provider's availability, network access rules, TLS requirements, storage, and backup policy are independent of Render and must be configured there.

## Local container run

For local development, use the bundled MySQL Compose service:

```sh
docker compose up --build
```

The Compose credentials are for local development only. Do not reuse them in Render or any shared environment.
